Python bir “prefix” (kurulum kök klasörü) kullanır. Standart kütüphane ve paketler bu klasörün altında aranır.

sys.base_prefix: Sisteme kurulu asıl Python’un kök klasörü. Venv içinde olsan da dışında olsan da hep aynı yeri gösterir (Linux’ta genelde /usr).

sys.prefix: Şu an çalışan ortamın kök klasörü.

Venv aktif değilse: base_prefix ile aynıdır (/usr).
Venv aktifse: venv klasörünü gösterir (/home/x/module05-bis/lab_env).

“Requirements files” are files containing a list of items to be installed using pip install like so:

Unix/macOS
python -m pip install -r requirements.txt

Dosyadaki paketlerin hangi sırayla kurulacağına güvenme. Pip sırayı garanti etmez.
Dosya bir URL’den de okunabilir, merkezi bir yerde tutulabilir.

1. pip freeze sonucunu saklamak
python -m pip freeze > requirements.txt
python -m pip install -r requirements.txt
pip freeze, ortamda kurulu her şeyi tam sürümüyle listeler 
Bağımlılıkların bağımlılıkları da buna dahil.
Başka bir makinede pip install -r yapınca birebir aynı sürümler kurulur. 

Senin ex0'daki karşılığı: requirements.txt bu mantıkla pin’lenebilir. 
Ama subject’in pandas>=2.1.0 gibi aralık yazan hali de kabul edilir. 
İkisi arasındaki fark, aralık yazarsan kurulum zamanında çıkan en yeni uyumlu sürümü almandır. 
Subject’in “pip resolves it at install time” cümlesi bunu anlatıyor.

import_module(name, package=None) fonksiyonu iki argüman alır:

name: Hangi modülün içe aktarılacağını belirtir. Bu isim mutlak (absolute) ya da göreli (relative) olabilir.

package: Eğer name göreceli bir ifade (. veya .. gibi) içeriyorsa,
bu argümanın doldurulması zorunludur. Hangi paketin referans (anchor) alınacağını söyler.
