The open() function takes two parameters; filename, and mode.

There are four different methods (modes) for opening a file:

"r" - Read - Default value. Opens a file for reading, error if the file does not exist

"a" - Append - Opens a file for appending, creates the file if it does not exist

"w" - Write - Opens a file for writing, creates the file if it does not exist

"x" - Create - Creates the specified file, returns an error if the file exists

In addition you can specify if the file should be handled as binary or text mode

"t" - Text - Default value. Text mode

"b" - Binary - Binary mode (e.g. images)

Because "r" for read, and "t" for text are the default values, you do not need to specify them.

Buffer nedir? Python write() dediğinde veriyi hemen diske göndermez, önce RAM'deki bir tampona (buffer) koyar. Gerçek diske yazma işlemi daha sonra olur: tampon dolunca, flush() çağrılınca ya da close() sırasında. Bu yüzden write() hızlıdır ve çoğu zaman başarılı döner.

When you enter a given context, the context manager’s .__enter__() method allocates the managed resources. When you exit the context, the .__exit__() method releases the resources and cleans up. 
Why Do We Need Context Managers?
Automatic cleanup: Frees resources like files or connections without manual effort.
Avoid resource leaks: Ensures proper release, even if errors occur.
Cleaner code: Replaces verbose try-finally blocks with with.
Exception-safe: Always performs cleanup, even on exceptions.
Custom control: Lets you manage any resource using __enter__ and __exit__.
Evet, dosya nesnesinin __enter__ ve __exit__ metotları her zaman vardır. Bunlar open() ile oluşan nesnenin (io.TextIOWrapper) kendi metotlarıdır, with yazıp yazmaman bunu değiştirmez.

Fark şu: with yazmazsan bu metotlar otomatik çağrılmaz. Onları çağıran şey with'in kendisidir. Sen fd = open(...) yazarsan nesne oluşur, metotlar orada durur ama kimse çağırmaz. Bu yüzden close()'u elle yazman gerekir.

f = open("a.txt")      # __enter__ / __exit__ var ama çağrılmadı
f.close()              # kapatmayı sen yapıyorsun

with kullanınca Python bu iki metodu senin yerine, doğru zamanda çağırır. Dosya nesnesinin __exit__'i içinde de close() çalışır, yani with = "__exit__ çağrılmasını garanti et" demek.

Bu arada __exit__'in dosya için yaptığı iş close() olduğundan, istersen f.__exit__(None, None, None) yazarak elle de çağırabilirsin ve dosya kapanır. Ama kimse böyle yazmaz, sırf mekanizmayı anlamak için bir bilgi.
class ContextManager:
    def __init__(self):
        print('init method called')
        
    def __enter__(self):
        print('enter method called')
        return self
    
    def __exit__(self, exc_type, exc_value, exc_traceback):
        print('exit method called')

with ContextManager() as manager:
    print('with statement block')
Output:

init method called
enter method called
with statement block
exit method called

Dosya örneğinde: __enter__() dosya nesnesinin kendisini döndürür. Yani with open(...) as f yazınca f, open()'ın döndürdüğü nesneyle aynı nesnedir. Bu yüzden "context manager = dosya nesnesi" gibi düşünmek kolay.
Neden bunu okudun/anlaman gerekiyor? Şunu göstermek için: with X as Y yazdığında Y, X'in kendisi olmak zorunda değil, X.__enter__() ne döndürürse odur. Dosyalarda aynı nesne çıkıyor, ama genel kural bu.
